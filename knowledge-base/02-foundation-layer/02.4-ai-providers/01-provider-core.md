# 01 — Provider 核心

> 读完本章你将理解:Provider 抽象层的"地基"由哪些模块组成,API 注册表如何工作,主机策略端口为何由嵌入应用注入,以及环境密钥解析为何要兼容浏览器与 Node 双环境。

## 一句话定位

Provider 核心是抽象层的第二层,承上启下:
- 向上为 Agent Runner 提供统一的流式调用入口
- 向下为各厂商适配器提供注册与加载机制
- 横向为主机策略、密钥解析、会话资源提供注入点
- 类型与校验从核心契约包重导出,保持单一契约源

## 组件清单

Provider 核心由 9 个模块协作:

| 组件 | 职责 | 关键约束 |
|---|---|---|
| **API 注册表** | 按 API 类型注册与查找流式适配器,管理来源标记 | 惰性加载;支持按来源批量卸载;类型擦除后存储 |
| **主机策略端口** | 定义 fetch 守卫、密钥脱敏、端点校验、诊断日志的接口 | 默认实现是惰性的;嵌入应用负责注入生产实现 |
| **环境密钥解析** | 从环境变量与配置文件解析 API Key | 浏览器构建禁用顶层 Node 模块导入;动态加载内置模块 |
| **Provider 选项** | 定义各厂商的参数类型(思考级别、缓存控制等) | 类型化选项;与厂商 SDK 解耦 |
| **内置注册入口** | 注册全部内置适配器,提供测试重置 | 只注册加载器,不触发 import;标记为内置来源 |
| **会话资源追踪** | 绑定会话上下文,管理资源生命周期与取消信号 | 会话级隔离;取消信号贯穿整个流式调用 |
| **流式辅助** | 事件流管道构造、背压处理、延迟事件缓冲 | 统一事件流契约;异步推送同步返回 |
| **共享类型** | 模型、消息、工具、流、上下文的统一类型定义 | 从核心契约包重导出;不在此层定义新类型 |
| **校验器** | 输入合法性与结构校验 | 从核心契约包重导出;契约单一来源 |

### 主机策略端口的注入模型

```
   ┌──────────────────────────────────────────────┐
   │  AI 包(本层)                                │
   │                                              │
   │  主机策略端口:                               │
   │  • 定义接口(fetch 守卫 / 脱敏 / 校验)       │
   │  • 默认实现 = 惰性的(安全但不做任何事)     │
   │  • 外部消费者不接线也能用(只是没有策略)    │
   └──────────────────────┬───────────────────────┘
                          │
                          │ 嵌入应用注入生产实现
                          │
   ┌──────────────────────▼───────────────────────┐
   │  OpenClaw 核心运行时(嵌入应用)              │
   │                                              │
   │  生产实现:                                   │
   │  • fetch 守卫 → 端点白名单 / 代理注入        │
   │  • 密钥脱敏 → 日志中隐藏 API Key             │
   │  • 端点校验 → 拦截非法请求目标               │
   │  • 诊断日志 → 结构化可观测                   │
   └──────────────────────────────────────────────┘

   为什么这样设计:
   • AI 包是可独立复用的,不应依赖 OpenClaw 核心
   • 外部项目用 AI 包时,不需要 OpenClaw 的策略实现
   • OpenClaw 嵌入时,通过注入把策略接上
```

## 协作流程

### 一次 LLM 调用中核心模块的协作

下面追踪 Agent Runner 发起调用时,Provider 核心各模块如何配合。

```
Agent Runner 发起 LLM 调用(携带模型 + 上下文)
         │
         ▼
┌──────────────────────────────────────────────────────────────┐
│ 1. 查找适配器                                                 │
│    → API 注册表按模型的 API 类型查找                         │
│    → 找到惰性加载包装                                        │
│    → 同步返回事件流(后台异步 import 厂商 SDK)              │
└────────────────────────────┬─────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ 2. 密钥解析                                                   │
│    → 环境密钥解析器按 Provider 名称查找对应 API Key         │
│    → 优先级:进程环境变量 > 配置文件 > 默认凭证路径          │
│    → Node 环境动态加载内置模块读取文件                     │
│    → 浏览器环境只走环境变量                                  │
└────────────────────────────┬─────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ 3. 主机策略注入                                               │
│    → 主机策略端口提供 fetch 守卫                             │
│    → 守卫做:密钥脱敏(日志)/ 端点校验 / 代理注入           │
│    → OpenClaw 核心注入生产实现;外部消费者用默认惰性实现    │
└────────────────────────────┬─────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ 4. 会话资源绑定                                               │
│    → 会话资源追踪器绑定当前会话上下文                        │
│    → 注入取消信号(用户取消时传播到流式调用)                │
│    → 资源生命周期与会话对齐(会话结束清理资源)              │
└────────────────────────────┬─────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ 5. Provider 选项应用                                          │
│    → Provider 选项模块提供厂商参数类型                       │
│    → 思考级别、缓存控制、推理强度等参数应用到请求            │
│    → 选项类型化,与厂商 SDK 解耦                             │
└────────────────────────────┬─────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ 6. 流式辅助构造事件管道                                       │
│    → 流式辅助模块构造事件流管道                              │
│    → 异步推送:厂商事件 → 翻译 → 统一事件 → 管道            │
│    → 同步返回:调用方立即拿到事件流(后台填充)              │
│    → 背压处理:消费慢时缓冲,不丢事件                       │
└────────────────────────────┬─────────────────────────────────┘
                             ▼
                  流式事件流交给 Agent Runner
```

## 关键设计约束

### 1. API 注册表惰性加载

- **为什么**:一次性加载全部厂商 SDK 会拖慢启动、占用内存;大多数部署只用一两个厂商
- **怎么做**:注册时只记录加载器函数;首次调用才触发 import;加载结果缓存复用;同步返回事件流,异步加载在后台进行
- **影响**:首次调用有 import 延迟但调用方无感知;后续调用直接复用缓存;测试可重置注册表

### 2. 主机策略端口由嵌入应用注入

- **为什么**:AI 包是可独立复用的库,不应依赖 OpenClaw 核心的策略实现;外部消费者可能有自己的安全策略
- **怎么做**:AI 包定义接口与惰性默认实现;OpenClaw 核心启动时注入生产实现(fetch 守卫 / 密钥脱敏 / 端点校验)
- **影响**:外部消费者不接线也能安全使用(惰性默认);OpenClaw 嵌入时策略生效;策略变更只改注入方

### 3. 环境密钥解析兼容浏览器与 Node

- **为什么**:AI 包需要同时支持 Node 服务端与浏览器端构建;浏览器遇到 Node 内置模块会报错
- **怎么做**:禁用顶层 Node 模块导入;运行时动态加载文件系统 / 操作系统 / 路径等内置模块;新版 Node 用内置模块获取 API;浏览器环境只走环境变量
- **影响**:同一套代码兼容双环境;浏览器构建不会因 Node 模块报错;Node 环境仍能读取凭证文件

### 4. 类型与校验从核心契约包重导出

- **为什么**:契约单一来源;避免在 AI 包中重复定义类型导致不一致;外部消费者可只引用核心契约包
- **怎么做**:AI 包的共享类型模块与校验模块从核心契约包重导出;不在 AI 包中定义新契约类型
- **影响**:类型变更只改核心契约包,所有重导出自动同步;外部消费者有选择引用哪个包的灵活性

### 5. 来源标记管理注册来源

- **为什么**:需要区分内置适配器与插件注册的适配器;测试需要重置到干净的内置状态;插件卸载需要批量清理
- **怎么做**:每个注册记录附带来源标识;内置来源有固定标识;卸载按来源标识批量操作
- **影响**:插件可安全注册与卸载;测试可重置到已知状态;多个插件不会互相干扰

## 设计观察

### 为什么主机策略用注入而非硬编码

```
错误设计:
   AI 包内部直接实现 fetch 守卫
   → 外部消费者被迫接受 OpenClaw 的策略
   → 外部项目有自己的端点白名单 → 无法定制
   → AI 包依赖 OpenClaw 核心策略实现 → 循环依赖

正确设计:
   AI 包定义接口 + 惰性默认实现
   → 外部消费者不接线 → 用惰性默认(安全但无策略)
   → OpenClaw 嵌入 → 注入生产实现
   → 外部项目可注入自己的策略
   → AI 包不依赖任何嵌入方
```

### 为什么注册表返回同步事件流

```
错误设计:
   首次调用时等待 import 完成才返回
   → 调用方阻塞,无法快速响应
   → 大 SDK 加载耗时数百毫秒
   → 用户体验差

正确设计:
   同步返回事件流,异步 import 在后台
   → 调用方立即拿到事件流对象
   → import 完成后事件流入事件流
   → import 失败时错误事件入事件流
   → 调用方逻辑统一(无需区分首次/后续)
```

### 为什么用两种流式函数

```
单一函数设计:
   只有完整流式函数(需要结构化选项)
   → Agent Runner 每次都要构造完整选项
   → 简单场景过度复杂
   → 插件默认场景门槛高

双函数设计:
   完整流式函数 → 结构化选项,给需要精细控制的调用方
   简化流式函数 → 简化选项,给 Agent Runner / 插件默认场景
   → 简单场景用简化函数,门槛低
   → 精细控制场景用完整函数,能力强
   → 两个函数共享惰性加载缓存
```
