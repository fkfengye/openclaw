# 03 — 提示词与模型

> 读完本章你将理解:系统提示如何被组装(工具/指南/项目上下文/技能),模型如何被解析与作用域匹配,以及为什么模型注册表运行时是会话层访问模型的唯一入口。

## 一句话定位

提示词与模型层是会话与 LLM 之间的**抽象边界**:
- 系统提示构建器把工具、指南、项目上下文、技能组装成最终 prompt
- 模型解析器按作用域匹配模型并做初始选择,思考级别用固定枚举约束
- 模型注册表运行时是会话层访问模型注册表的唯一入口,会话层不绑定特定厂商

## 组件清单

提示词与模型层由 5 个组件协作:

| 组件 | 职责 | 关键约束 |
|---|---|---|
| **系统提示构建器** | 组装工具/指南/项目上下文/技能为最终 prompt | 自定义提示可整体替换默认 |
| **提示模板** | 模板定义与选择 | 模板由调用方指定 |
| **模型解析器** | 作用域匹配,别名识别,思考级别解析,初始选择 | 思考级别固定枚举,非法值拒绝 |
| **模型注册表运行时入口** | 会话层访问注册表的唯一入口 | 运行时获取,不直接持有 |
| **模型注册表** | 模型集合与元数据存储 | 由 Provider 插件填充,会话层只读 |

## 协作流程

### 一次 prompt 构建与模型解析的接力

下面追踪会话从请求构建 prompt 到选定模型的完整过程。

```
会话生命周期层请求构建 prompt + 解析模型
         │
         ▼
┌──────────────────────────────────────────────────────────────┐
│ 1. 模型注册表运行时入口                                      │
│    → 获取当前模型注册表(由 Provider 插件填充)              │
│    → 注册表是运行时快照,进程稳定                            │
└────────────────────────────┬─────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ 2. 模型解析器                                                │
│    → 输入:用户指定的模式串(可能含思考级别)               │
│    → 识别别名:无日期后缀 / -latest 视为别名                │
│    → 作用域匹配:在注册表范围内匹配                          │
│    → 思考级别:固定枚举校验(off/minimal/low/medium/high/…)│
│    → 初始选择:无指定时用默认模型与默认 provider            │
└────────────────────────────┬─────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ 3. 系统提示构建器                                            │
│    → 自定义提示?整体替换默认                               │
│    → 否则组装默认提示:                                      │
│      • 工具片段(按选中工具注入)                            │
│      • 指南条目(默认 + 追加)                               │
│      • 项目上下文(README/示例/文档,预加载或现读)          │
│      • 技能(格式化后注入)                                  │
│    → 追加额外文本                                            │
└────────────────────────────┬─────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ 4. 输出送 Provider                                           │
│    → 系统提示 + 会话历史 + 工具表 → Provider 插件 → LLM     │
└──────────────────────────────────────────────────────────────┘
```

### 自定义提示 vs 默认提示的替换语义

为什么自定义提示是整体替换而非合并?用反例说明。

```
场景:用户想用自定义提示

合并式(错误):
   默认提示 + 自定义提示 → 拼接
   → 默认指南与自定义指南冲突
   → 工具片段重复
   → 上下文混乱

替换式(正确):
   自定义提示存在 → 整体替换默认
   自定义提示缺失 → 用默认 + 追加条目
   → 职责清晰:要么全自定义,要么基于默认扩展
   → 追加条目(指南/文本)只在默认模式下生效
```

## 关键设计约束

### 1. 模型解析由 Provider 插件提供

- **为什么**:会话层不绑定特定厂商,切换 LLM 只换 Provider 插件
- **怎么做**:模型注册表由 Provider 插件填充,会话层通过运行时入口只读访问
- **影响**:同一 Agent 可配置不同 Provider(OpenAI/Anthropic/本地)

### 2. 思考级别固定枚举

- **为什么**:防止非法值传入 Provider 导致请求失败或行为异常
- **怎么做**:解析时校验思考级别是否在固定枚举内,非法值拒绝
- **影响**:思考级别只能从 off/minimal/low/medium/high/xhigh/max 中选

### 3. 模型注册表运行时是唯一入口

- **为什么**:注册表是进程稳定的元数据,不应被会话层直接持有或重复加载
- **怎么做**:会话层通过运行时入口获取注册表快照,不直接 import 注册表模块
- **影响**:注册表变更需重启或显式 owner 重载,不在热路径刷新

### 4. 系统提示构建可整体替换

- **为什么**:用户可能完全自定义提示,默认指南不适用
- **怎么做**:自定义提示存在时整体替换默认;追加条目只在默认模式下生效
- **影响**:自定义模式与默认模式互斥,不混合

### 5. 项目上下文预加载可选

- **为什么**:预加载避免热路径文件读取,但不是所有场景都需要
- **怎么做**:构建选项支持预加载上下文文件,未预加载时现读
- **影响**:调用方可按性能需求选择预加载或现读

## 设计观察

### 为什么别名识别用日期后缀而非显式标记

```
显式标记方案:
   每个模型注册时声明 "我是别名"
   → 注册逻辑变复杂
   → Provider 插件要额外维护标记

日期后缀方案(当前):
   • ID 以 -YYYYMMDD 结尾 → 视为具体版本
   • ID 以 -latest 结尾或无日期后缀 → 视为别名
   → 无需额外标记,从 ID 形态推断
   → Provider 插件无需改注册逻辑
   代价:依赖命名约定,但业界模型 ID 普遍遵循此模式
```

### 为什么模型注册表运行时单独成入口

```
错误设计:
   会话层 ──直接 import──► 模型注册表模块
   → 会话层持有注册表实例
   → 注册表变更时多处持有过期快照

正确设计:
   会话层 ──► 模型注册表运行时入口 ──► 获取当前快照
   → 单一入口,进程稳定
   → 注册表变更走 owner 重载流程,不散落刷新
   → 符合"网关/插件元数据进程稳定"的硬约束
```
