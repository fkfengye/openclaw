# 04 — 退出监控

> 读完本章你将理解:外部脚本进程退出如何被监听、流式触发任务的生命周期如何管理、stop 原因契约如何统一所有启停决策、为什么退出监控放在网关层而非 cron 子目录。

## 一句话定位

退出监控是定时任务与外部进程世界的"桥梁":
- 进程退出监听组件(on-exit)监听外部脚本退出,一次性触发关联任务
- 流式触发监控组件(stream)管理长生命周期的流式触发任务,定期对账
- 两类组件都直连进程监管器,因此放在网关层而非 cron 子目录
- stop 原因走单一契约,所有直接变更与对账决策共用同一解析器

## 组件清单

| 组件 | 职责 | 关键约束 |
|---|---|---|
| **进程退出监听** | 监听外部脚本退出,一次性触发关联任务 | 24 小时安全超时,防止挂死进程拖住网关 |
| **流式触发监控** | 管理流式触发任务集合,定期对账启停 | 单任务单属主,stop 原因走单一契约 |
| **流式任务属主** | 拥有单个流式任务的生命周期(拉起 / 重启 / 退役) | 连续失败上限,稳定运行阈值控制退役 |
| **流式输出处理** | 处理流式任务的输出,决定开火 / 丢弃 / 损失原因 | 输出交错有界,防无限积压 |
| **Stop 原因契约** | 统一所有启停决策的 stop 原因解析 | 禁用类 / 生命周期类两大族 |
| **退出监听壳** | 解析 on-exit 任务的 shell 命令 | 与平台 shell 对齐,可注入自定义 shell |
| **装填令牌** | 标识当前装填的所有权,防止异步拉起错配 | 槽位同步预留,异步拉起失效即无操作 |

## 关联关系

### 两类监控组件的职责差异

```
   进程退出监听(on-exit):
   ┌─────────────┐
   │ 外部脚本    │ ──退出──► 一次性触发关联任务 ──► 完成
   └─────────────┘
   • 一次性:脚本退出即触发,不重启
   • 24 小时安全超时:防挂死
   • 装填令牌防异步拉起错配

   流式触发监控(stream):
   ┌─────────────┐
   │ 流式源      │ ──持续运行──► 定期输出 ──► 开火 / 丢弃
   └─────┬───────┘
         │ 故障
         ▼
   重启(连续失败 < 上限)
         │
         ▼
   连续失败 ≥ 上限 ──► 退役

   • 长周期:持续运行,定期对账
   • 单任务单属主:防重复拉起
   • 稳定运行阈值:达到阈值才允许退役
```

### Stop 原因契约的两族

```
   禁用类:
   ├─ disabled        (任务被禁用)
   ├─ trust-disabled  (信任级被禁用)
   └─ cron-disabled   (cron 整体被禁用)

   生命周期类:
   ├─ removed           (任务被删除)
   ├─ shutdown          (网关关闭)
   ├─ schedule-update   (调度更新)
   ├─ restart-exhausted (重启次数耗尽)
   └─ trigger-disabled  (触发器被禁用)

   反例:各调用点自定义字符串
   调用点 A:"stopped"
   调用点 B:"disabled"
   调用点 C:"removed"
   → 重装 / 清理逻辑得分发多个字符串 → 分叉 → 不一致
```

### 流式任务属主与进程监管器

```
   流式任务属主
        │
        ├─启动──► 进程监管器拉起进程 ──► 返回受管运行句柄
        │                                       │
        │                                       ▼
        │                                  等待进程退出
        │                                       │
        │      ┌────────────────────────────────┘
        │      │
        │      ▼ 退出
        │   判断退出原因
        │      ├─ 正常退出 + 稳定运行过阈值 ──► 退役
        │      ├─ 正常退出 + 未达阈值      ──► 重启
        │      ├─ 错误退出 + 失败 < 上限   ──► 重启(退避)
        │      └─ 错误退出 + 失败 ≥ 上限   ──► 退役
        │
        └─停止──► 进程监管器按作用域键取消进程

   反例:无属主,直接拉起进程
   → 多个调用方各自拉起同一任务 → 重复进程 → 资源浪费
```

## 协作流程

### on-exit 任务的完整监听流程

```
调度服务加载 on-exit 任务
         │
         ▼
┌──────────────────────────────────────────────────────────────┐
│ 1. 对账                                                      │
│    接收当前所有 on-exit 任务                                 │
│    • 新增任务 → 装填(装填监听)                             │
│    • 已有任务 → 检查命令是否变更 → 变更则重新装填            │
│    • 已删除任务 → 取消(取消监听)                           │
└─────────────────────────────┬────────────────────────────────┘
                              ▼
┌──────────────────────────────────────────────────────────────┐
│ 2. 装填(装填监听)                                           │
│    • 同步预留槽位 + 生成新装填令牌                           │
│    • 解析 shell 命令(经退出监听壳)                         │
│    • 异步拉起进程(经进程监管器)                            │
│    • 启动 24 小时安全超时                                   │
└─────────────────────────────┬────────────────────────────────┘
                              ▼
┌──────────────────────────────────────────────────────────────┐
│ 3. 等待退出                                                  │
│    • 进程退出 → 进入步骤 4                                  │
│    • 24 小时超时 → 视为退出,进入步骤 4                     │
│    • 装填令牌失效(被重新装填 / 取消)→ 无操作,放弃结果    │
└─────────────────────────────┬────────────────────────────────┘
                              ▼
┌──────────────────────────────────────────────────────────────┐
│ 4. 触发关联任务                                              │
│    • 收集退出码、原因、stdout、stderr、是否超时             │
│    • 调用调度服务的退出触发回调                              │
│    • 调度服务把退出结果作为触发信号,走正常执行路径          │
└─────────────────────────────┬────────────────────────────────┘
                              ▼
┌──────────────────────────────────────────────────────────────┐
│ 5. 持久化完成状态                                            │
│    • 调用调度服务的完成持久化回调                            │
│    • 标记 on-exit 任务已完成(一次性)                       │
│    • 从活跃任务集合移除                                      │
└──────────────────────────────────────────────────────────────┘
```

### 流式触发任务的对账流程

```
调度服务定期触发对账
         │
         ▼
┌──────────────────────────────────────────────────────────────┐
│ 1. 计算差异                                                  │
│    当前流式任务集合 vs 已监控任务集合                       │
│    • 新增任务 → 启动                                         │
│    • 已有任务 → 检查触发器开关                               │
│    • 已删除任务 → 停止                                       │
└─────────────────────────────┬────────────────────────────────┘
                              ▼
┌──────────────────────────────────────────────────────────────┐
│ 2. 应用对账决策                                              │
│    • 解析 stop 原因(经 Stop 原因契约)                      │
│    • 触发器关闭 → 以 trigger-disabled 停止                  │
│    • cron 整体关闭 → 以 cron-disabled 停止                  │
│    • 任务删除 → 以 removed 停止                              │
│    • 新增 / 触发器开启 → 启动                                │
└─────────────────────────────┬────────────────────────────────┘
                              ▼
┌──────────────────────────────────────────────────────────────┐
│ 3. 流式任务属主接管                                          │
│    • 拉起流式源(经进程监管器)                              │
│    • 等待输出                                                │
│    • 输出经流式输出处理 → 开火 / 丢弃 / 损失                │
│    • 开火 → 调用调度服务触发关联任务                        │
└─────────────────────────────┬────────────────────────────────┘
                              ▼
┌──────────────────────────────────────────────────────────────┐
│ 4. 故障处理                                                  │
│    • 进程退出 → 判断原因                                     │
│    • 错误退出 + 失败次数 < 上限 → 重启(退避)              │
│    • 错误退出 + 失败次数 ≥ 上限 → 以 restart-exhausted 停止│
│    • 稳定运行过阈值后退出 → 退役(允许)                    │
└──────────────────────────────────────────────────────────────┘
```

## 关键设计约束

### 1. 退出监控放在网关层而非 cron 子目录

- **为什么**:退出监控直接依赖进程监管器(网关层组件),若放在 cron 子目录会迫使 cron 反向依赖网关,破坏边界
- **怎么做**:退出监控组件放在网关层,组合进程监管器 + cron 任务身份;cron 子目录只提供任务类型与契约
- **影响**:cron 子目录不感知进程监听,可独立测试

### 2. on-exit 任务有 24 小时安全超时

- **为什么**:被监听的命令可能挂死或永不退出,没有超时会拖住整个网关进程
- **怎么做**:24 小时超时(慷慨,因为合法监听包括构建 / 部署等长任务);超时后视为退出,触发关联任务
- **影响**:挂死进程最多拖住 24 小时,不会永远拖住网关

### 3. 装填令牌防异步拉起错配

- **为什么**:装填是异步操作(拉起进程需要等待),在等待期间任务可能被重新装填或取消,旧拉起的结果若直接应用会错配
- **怎么做**:装填时同步预留槽位 + 生成新装填令牌;异步拉起完成后检查令牌,失效则无操作
- **影响**:并发装填 / 取消不会产生幽灵监听

### 4. 流式任务单属主 + 连续失败上限

- **为什么**:多个调用方各自拉起同一任务会重复进程、浪费资源;无失败上限会让故障任务无限重启
- **怎么做**:单任务单属主,属主独占生命周期;连续失败次数有上限,达到上限以 restart-exhausted 停止
- **影响**:故障任务最终退役,不会无限重启拖累系统

### 5. Stop 原因走单一契约

- **为什么**:启停决策分散在对账、直接变更、生命周期事件多个调用点,各自定义字符串会让重装 / 清理逻辑分叉
- **怎么做**:Stop 原因契约组件提供两大族(禁用类 / 生命周期类)的统一解析;所有调用点走同一契约
- **影响**:新增 stop 场景必须扩展契约,不能各自定义字符串

### 6. 稳定运行阈值控制退役

- **为什么**:流式源刚启动就退出可能是启动失败,直接退役会让本可恢复的任务永久停止;但运行过阈值后退出更可能是正常结束
- **怎么做**:设稳定运行阈值(默认 60 秒);未达阈值退出 → 重启;达阈值退出 → 允许退役
- **影响**:启动抖动不致永久退役,真正稳定运行后的退出才退役

## 设计观察

### 为什么 on-exit 与 stream 分成两类组件

```
合并设计:
   一个组件同时处理 on-exit 和 stream
   → 一次性语义(不重启)与长周期语义(重启 + 退役)混淆
   → 超时策略不同(24h vs 稳定运行阈值)→ 互相干扰

分离设计:
   on-exit 组件:一次性,24h 超时,退出即触发
   stream 组件:长周期,重启 + 退役,稳定运行阈值
   → 各自语义清晰,超时 / 重启策略独立
```

### 为什么流式输出处理单独成组件

```
内嵌在属主中:
   属主 ──内嵌输出处理──► 调度服务
   → 输出交错、丢失原因、开火决策混在属主里 → 属主臃肿
   → 输出处理无法独立测试

分离设计:
   属主 ──► 流式输出处理 ──► 调度服务
   → 属主只管进程生命周期
   → 输出处理只管开火 / 丢弃 / 损失归类
   → 各自可独立测试
```

### 为什么对账走 stop 原因契约而非直接删除

```
直接删除:
   对账发现任务不在新集合 → 直接从内部映射删除
   → 进行中的进程无人清理 → 资源泄漏
   → 终态不通知调度服务 → 调度服务状态不一致

走契约:
   对账发现任务不在新集合 → 以 removed 停止 → 走正常停止流程
   → 取消进行中的进程(按作用域键)
   → 终态通知调度服务
   → 调度服务状态与监控组件状态一致
```
