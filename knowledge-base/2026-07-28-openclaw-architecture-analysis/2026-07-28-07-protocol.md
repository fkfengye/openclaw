# 07 — Gateway 协议

## 7.1 版本

[packages/gateway-protocol/src/version.ts](file:///d:/DevSpace/person/ai_space/openclaw/packages/gateway-protocol/src/version.ts):

```typescript
/** Current gateway protocol version emitted by modern clients and servers. */
export const PROTOCOL_VERSION = 4 as const;
/** Lowest general client protocol version accepted by the gateway. */
export const MIN_CLIENT_PROTOCOL_VERSION = 4 as const;
/** Lowest authenticated node protocol version accepted by the gateway. */
export const MIN_NODE_PROTOCOL_VERSION = 3 as const;
/** Lowest lightweight probe protocol version accepted by the gateway. */
export const MIN_PROBE_PROTOCOL_VERSION = 3 as const;
```

| 常量 | 值 | 含义 |
|---|---|---|
| `PROTOCOL_VERSION` | 4 | 当前协议版本(modern clients/servers) |
| `MIN_CLIENT_PROTOCOL_VERSION` | 4 | 接受的最低 client 版本 |
| `MIN_NODE_PROTOCOL_VERSION` | 3 | 接受的最低 authenticated node 版本 |
| `MIN_PROBE_PROTOCOL_VERSION` | 3 | 接受的最低 lightweight probe 版本 |

**注意**:client 最低 4(与当前版本一致),说明 client 协议已发生过 breaking change;node/probe 仍兼容到 3。

## 7.2 版本变更约束

AGENTS.md "Architecture" 段明确:

> Gateway protocol changes: additive first; incompatible needs versioning/docs/client follow-through.
> Protocol version bumps: explicit owner confirmation only; never automatic/generated.

**关键约束**:
- 协议变更**优先 additive**(向后兼容)
- 不兼容变更需要 versioning + docs + client follow-through
- 版本 bump **不可自动生成**,需 owner 显式确认

## 7.4 关键观察

- **子包独立**:`packages/gateway-protocol` 不依赖核心 session 类型,可独立演进。
- **Schema 分片**:13 个 fragment 按领域拆分,避免单文件巨型 schema。
- **TypeBox 选型**:结构化 + 类型推导友好(对比 zod,更轻量、编译期优化更好)。
- **版本兼容**:client 必须 v4,node/probe 兼容到 v3 — 说明 client 协议演进更快,node 协议更稳定。
- **版本 bump 严控**:不可自动生成,需 owner 显式确认,保护协议稳定性。

```
                    Gateway Server

        │                │                │

   │ Client  │      │  Node   │      │  Probe  │

   │  一致)  │      │         │      │         │
   └─────────┘      └─────────┘      └─────────┘

    版本演进趋势:
    ┌──────────────────────────────────────────────────────┐
    │ Client 协议:v3 → v4(已发生 breaking change)       │
    │   → 说明 client 协议演进更快,要求严格对齐          │
    │                                                      │
    │ Node 协议:仍兼容 v3                                 │
    │   → 说明 node 协议更稳定,演进慢                    │
    │                                                      │
    │ Probe 协议:仍兼容 v3                                │
    │   → 说明 probe 是轻量级,兼容性优先                │
    └──────────────────────────────────────────────────────┘

    版本变更决策树:
    ┌──────────────────────────────────────────────────────┐
    │ 想变更协议?                                         │
    │                                                      │
    │ ├─ 是 additive(向后兼容)?                          │
    │ │   └─ Yes → 可以直接加,不 bump 版本               │
    │ │                                                      │
    │ ├─ 是 breaking(不兼容)?                             │
    │ │   └─ Yes → 必须 bump 版本                          │
    │ │       ├─ 需要 owner 显式确认(不可自动生成)        │
    │ │       ├─ 需要更新 docs                             │
    │ │       └─ 需要 client follow-through                │
    │ │                                                      │
    │ └─ 不确定?                                          │
    │     └─ 默认按 breaking 处理,问 owner                │
    └──────────────────────────────────────────────────────┘
```
